## 两轮闪退与当前修复

用户测试初版后报告推进到 12 月 12 日稳定闪退。2026-11-16 16:54:02 的崩溃记录为 `C00000FD / EXCEPTION_STACK_OVERFLOW`，转储中出现了新每日检测事件 `gcd_welyam.90`。初版把这个隐藏事件的检测与自我调度放进 `immediate`，并且它和清理事件 `gcd_welyam.2` 都缺少必需的 `option`。这两项结构风险未被初版的括号、引用、计时检查覆盖。

第一轮将循环移到自动选项，但用户随后在内战触发后再次闪退；2026-11-16 17:30:38 的转储仍为栈溢出，并仍出现 `gcd_welyam.90`。第一轮只检查 `immediate` 调用环不足以防止这个问题。

当前已彻底退役 .90 自我调度，按本机 `feiten_daily_pulse` 的模式在省份 221 挂原生每日翻转回调；旧存档残留的 .90 只接入新回调，不再安排自身。同一天最多运行一次；灾难结束且没有进行中的内战时移除回调。新事件通知延迟一天，避免在每日回调栈中直接进入界面事件链。检查器现在禁止本模组任何选项或即时块形成事件调用环，能拒绝上述两份历史版本。日志中的无效 `add_reform_progress` 同时改成有效的 `change_government_reform_progress = 25`。

本轮只完成文件与回归检查，新版内战与叛军行为尚待用户重新加载文件后验证。不会根据旧日志声称修复版已经实测成功。

同步前核对安装目录，发现 `a13_1_1` 和 `a13_2_1` 的图标已互换；保留本地已有选择并同步到仓库。其余前四列任务的结构与奖励保持不变。

## 开局与灾难

开局首个月度灾难检查时，A13 自动进入 `gcd_welyam_reform`，显示 `gcd_welyam.1`。事件选项将当时全部本国省份的自治度**设为 30**，不是增加 30。开局正文取自用户第一张截图；未提供的其他事件正文统一使用“事件正文待补”。

灾难修正为全国叛乱度 +2、贵族忠诚均衡点 −50%、政府改革点数增长 +20%。三个特殊机制的介绍写在灾难说明中：

1. 贵族忠诚低于 20 连续满 365 天，触发内战事件。每日检查；恢复到正好 20 也会重置计时。任务三第一分支可以永久阻止尚未发生的内战。
2. 两年一次的固定 **12k** 贵族叛军已接入：计时器到期投递一次专用隐藏事件 `gcd_welyam.91`，事件选择己方控制且没有部队的本国省份，生成贵族叛军后，通过 `num_of_units_in_province / who = REB` 计数并只裁剪本次新生成的叛军，校准为合计 12 个满员团。隐藏事件不自我调度，下一轮由灾难计时器安排。正常两次投递相隔 730 天，各延迟一天处理；没有合适空省时等待再投递。初始化不足时补生成；所有循环有上限，异常校准会回收本次新叛军并保留重试。已有军队或叛军不参与调整。事件实际执行时会再次检查灾难与任务二状态，结束灾难或完成任务二后，已排队的隐藏事件也不会刷兵。借款使用 Anbennar 已有的富商贷款禁用标记，完成任务二后解除。单位计数、生成、删除的实际引擎行为仍需用户实测。
3. 灾难期间，A13 主动对 A01（洛伦特）或当时的皇帝宣战，若 A24 是其属国且独立倾向严格大于 50，A24 独立并加入被宣战方。阿德肖叛乱现专指永冻边区以 `cb_gcd_adshaw_revolt` 发起的战争：符合相同灾难与独立倾向条件时，A24独立并加入永冻边区进攻方；不接到原版对灰王的复国战。

三个特殊机制均有灾难有效期检查；结束后不再启动。已经独立的国家、已经生成的叛军或已经开始的内战不因结束灾难而倒退。正常完成末项任务要求处于和平。

`gcd_welyam.100` 的选项先释放指定叛乱国的本国非首都核心，再执行 `release_all_possible_countries`，并让现有属国独立。大边区使用专用 CB `cb_gcd_gawedi_civil_war` 对 A13 宣战，战争目标为夺取首都，指定省份为加韦顿 221。其余五个点名国家加入大边区一方，威斯特摩尔不检查独立倾向。

外交 `requestpeace` 限制双方手动、单独议和；`enforce_peace` 限制第三国强制和平。空和平条款列表和很低的 AI 和平倾向仅作为补充，不能单靠它们声称禁止白和平。

只有两条胜负事件路径，先锁定结局，再由选项结算：

- 大边区战争攻击方成员控制加韦顿 → `gcd_welyam.101` → 大边区吞并 A13，并附庸 B83、B84、A52、A51。**不附庸 A24**。A13 玩家失去国家，不自动转交大边区。
- A13 对 A50 的战争分数达到 99 → `gcd_welyam.102` → A13 吞并 A50、B83、B84、A52、A51、A24。改革灾难仍须通过末项任务结束。

首都被普通叛军或无关第三国占领不会判为大边区胜利。每日检查及首都围城结束回调均核对专用 CB、A50/A13 两个战争领袖，避免无关战争误触发结算。首都控制者现在还须与 A13 敌对，并处于同一专用 CB 战争；不使用 `attackers=THIS`。

### 结局未触发的修正

本轮读取用户测试存档的只读局部数据，发现 A13 的 `gcd_welyam_civil_war_result_queued` 记录为 1450.6.17，到 1451.1.1 战争仍在继续，且存档没有 101/102 的待处理事件。旧代码先设队列标记，随后永远禁止再检查，形成确定的卡死路径。

新版分别记录“已选胜者”和“事件已实际送达”。只有结局事件真正进入时才设置送达标记；没有胜者记录的旧队列会迁移，三天未送达的新队列可以重投。首次选定的结局保持锁定；如果同一检查时刻同时达到两个条件，则首都陷落优先。增加国家 ROOT 的加载/月度补查，101/102 也改为可由国家事件系统独立触发的一次性事件，MTTH 为一天。脚本日检仍投递次日事件；独立事件系统的检查周期不等于每天，兜底触发可能有等待。

日检翻转改用显式 A13 国家标记，避免依赖隐式省份标记作用域。日志中未通过引擎校验的 `can_spawn_rebels=noble_rebels` 条件已从本模组省份筛选中移除；脚本强制起义仍保留所属、控制和空省检查。

回归包含低于 30 的严格边界、两事件分流、土地/忠诚即时变化、旧队列恢复、三天重投、送达后禁止重投、六个内战攻击国占领首都、无关第三国和叛军排除、99 分门槛及先到结局锁定。游戏存档未被修改，修复版还没有实机确认。

### 待用户实机确认的引擎行为

静态检查不能证明外交限制是否覆盖游戏内所有和平入口、国家释放后的自动军队与外交状态、AI 参战及吞并结算。正常开局 A50 原本不存在，释放后只有本场内战；EU4 的 `join_all_offensive_wars_of` 会加入领头国**所有**进攻战争，若在特殊旧存档中 A50 已独立且另有进攻战争，需要另行处理该边界。相同限制也适用于威斯特摩尔加入被宣战方的防御战争。

本轮没有添加未指定的叛乱国兵力奖励，也未启动或操控游戏。建议用户安排新加韦德测试局验证首月事件与分支；旧存档任务完成状态和配偶标记会影响新内容。

二年叛军测试必须使用尚未完成 `a13_5_2` 的存档；已完成第二任务的旧存档继续保留停止叛军效果，不回退玩家任务进度。旧版错误的王国等级门槛可能让该任务过早完成，这类存档不能用于验证两年叛军是否开始生成。

## 兼容与重建

新增独立脚本不覆盖魔法、奇械或决议 GUI。为了保留原有外交限制和卡丽娜创建事件，以下两份运行文件以当前本机 Anbennar 文件为基础生成，原内容逐字节保留，只有 `GCD_REFORM_BEGIN/END` 注释之间是新增片段：

- `common/diplomatic_actions/00_diplomatic_actions.txt`
- `events/Flavour_Gawed_A13.txt`

Anbennar 更新后，运行：

```powershell
python tools/build_reform_compat.py "你的 Anbennar 模组目录"
python tools/build_welyam_tier2.py "你的 Anbennar 模组目录"
python "制作源文件/EU4本地化转码.py" "制作源文件/威利亚姆改革_中文原文.yml" "localisation/gcd_welyam_reform_l_english.yml"
python tools/validate_reform.py "你的 Anbennar 模组目录" "你的 EU4 游戏目录"
python tools/check_encoding.py
```

生成器通过语法位置插入，保留其余上游内容；找不到预期事件或外交块时会失败，不会猜测插入位置。`制作源文件/改革兼容基线.json` 记录本次上游及生成文件的 SHA-256，不记录用户私人路径。

`build_welyam_tier2.py` 另从当前君主制第二层读取全部 94 个选项，生成该层的替换效果及 `改革二级政改基线.json`；不覆盖 Anbennar 的政府定义。单位回归覆盖原生返回 1～80 团时校准到 12、零生成及异常大数量时有限回收、既有军队不受影响；政改回归覆盖所有 94 个二级选项和其他层保留。这些是脚本模型与结构检查，不能替代 EU4 实测。
